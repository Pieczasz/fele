# Recommender back-test (last 2 development months)

Back-test of the recommender (Phase 9 acceptance): on the last BACKTEST_MONTHS development months, how often was
the team's actual pick in our top 1 / top 5, for the draft-action model alone and for the recommender's re-ranking
(model + composition + style + lane matchup)? A pick the engine can't offer counts as a miss.

Honest set-up: the draft model is trained only on series before those months; every feature comes from the
time-respecting feature store (state as of each game); style profiles use only earlier picks. The recommender's
weights are fixed by design and were not tuned on this. The holdout is not used: it served its one check in Phase 8
(the first version of this back-test ran on holdout drafts and skipped picks it couldn't offer, which inflated it).
Coach preferences exist only for Cloud9, so they are not part of the league-wide back-test.
Caveat: lane matchups come from the live-patch solo-queue sample, later than the holdout games.

- Picks: 1332; offerable: 1271 (actual pick was one of the engine's candidates; the rest count as misses); median 122 candidate champions per pick.

| | Draft model alone | Recommender (model + comp + style + lane) | Recommender - model [95% CI] |
|---|---|---|---|
| Actual pick is the top option | 12.7% | 12.9% | +0.2% [-0.8%, +1.2%] |
| Actual pick in the top 5 | 45.6% | 45.8% | +0.2% [-1.1%, +1.5%] |
| Mean reciprocal rank | 0.284 | 0.280 | |

Reading: matching what teams actually did is a sanity check, not the goal: the recommender is meant to add the coach's knowledge and composition sense on top of 'what pros do here'. Whether a recommended alternative would have *won more* can't be validated with this data: Phase 8 found draft effects on win probability too small to measure (docs/MODEL_CARD.md), so the engine labels its draft edge as weak evidence.
